# Arduino Field Lab 迭代路线图

状态：2026-10-22 首轮运行版完成。原站取证与自有应用的实现必须分别判卷；不得因为自己写的应用能运行，就宣称已达到第三方原站 1:1。

## 阶段 P0：可复核原站证据 — 已完成

- Playwright 采集 12 条语言路由、页面 HTML、运行时资源、网络与关键交互。
- `mirror/` 71 个文件、SHA-256 清单和外链豁免账本通过核验。
- `port/` 为镜像逐字节副本；15 个非 vendor Bundle 被切为 55 个可逐字节重组的区块。
- 实际复刻目标的边界：预设情景模拟不等于 Arduino C++ 编译；原始 308 路由规则与本地镜像服务器有可登记偏差。

验收：`verify-mirror` 5/5、`verify-reassembly` 15/15、离线无未授权资源调用。

## 阶段 P1：独立生长内核与前端 — 已实现第一版

- `scaffold/` 是可构建、可独立运行的 Web 产品；不读取本地原站 mirror。
- 16 个课程对象经注册表验证，11 类情景模拟器按 ID 装配；新增第 17 课不改总路由、组件和模拟器代码。
- 运行内核以 `SimulationEvent` 为事实源，统一派生引脚、测量值、串口和 Three.js 元件状态。
- 完成 Three.js 程序化板卡、选件、转视角、课程导航、运行/停止/单步/复位、按钮/滑杆、学习进度存储。
- 12 个 locale 路由可用，英语/简体中文翻译初版，其他十种语言明确显示回退。
- 桌面及手机端 Playwright 交互与静态资源零外联检查已通过。

验收：`cd scaffold && pnpm test && pnpm build && pnpm test:e2e`，另需实际产品验收/手动审阅场景品质。

## 阶段 P2：从情景演示变成真实学习 — 待实施

1. 将课程题目、接线任务、预期输出和错误解释建成独立 schema（目前已建立基本课程数据，但未含每课的可判卷练习）。
2. 先为 Blink、Button、Analog 三个课程设计输入/输出轨迹验收，学生必须预测结果、提交操作和验证再过关。
3. 补足 16 门课程的模拟验证案例，尽量使用纯函数而不是仅检查 DOM 文案。
4. 用统一 part/pin/cable 图扩展 3D：接线关系、极性、电源流、错接告警，增加真正的基础电路语义。
5. 完成与原站的视图/行为差异台账；这里有意设计独立产品，不强行消除所有像素差异。

固定点：新增一个同类型课程只新增数据、必要翻译与验收轨迹。不能改内核控制流程。

## 阶段 P3：代码与模拟器解耦 — 待实施

- 在 `SketchRuntime` 抽象下实现一个**明确约束的 Arduino 子集**：解析 pinMode / digitalRead / digitalWrite / analogRead / analogWrite / delay / tone 等基础函数。
- 真实解析器接入之前 UI 严禁宣称“真正编译/上传 C++”；当前 `Run scenario` 是正确的名称。
- 通过固定时钟、种子、事件回放，让相同代码+接线+输入在不同浏览器中产生一致结果。
- 后续可追加真机 Serial/WebUSB/WebSerial 适配层，但不是内核依赖。

## 阶段 P4：课程与部件生态 — 待实施

- 以独立的 `LessonPack`、`ComponentPack`、`SimulatorPlugin` 形式管理新的课程与元件。
- 区分真实电气模型、教学示意模型、场景预设模型三个可信度层级；明确每种能力的适用边界。
- 建立内容来源、版本、schema 兼容、自动化回归和回滚治理。
- 待确认许可后，再决定是否做原站逐像素复刻与资产继承；未授权原站镜像不进入公开版。

## 防烂尾机制

每轮只做一个可自动验收的纵切片：课程数据 → 输入事件 → 仿真状态 → 3D/串口投影 → 单测和浏览器测。任何所谓“又加了一个漂亮的部件”若没有新的行为合同和可复核测试，不计入核心能力进展。
