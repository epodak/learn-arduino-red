# website-rebuild-skill 的本地兼容补丁

日期：2026-10-22。当前 vendored skill 元数据版本为 `0.3.24`，来源为公开仓库 `boyang-hu/website-rebuild-skill`，采用 MIT License；许可证文本随 `.agents/skills/website-rebuild/LICENSE` 一并保留。以下补丁只用于当前仓库内的 skill 副本，目的是让工具链符合项目约束并在 Windows Node 24 下可靠退出；不是对上游仓库的提交。

## 1. 包管理器统一

`scripts/lib/npx.mjs` 保留原有导出名以减少调用点变化，但把 `npx -y <package>` 转成 `pnpm dlx <package>`。本项目只使用 pnpm，不允许脚本隐式使用 npm/npx。

## 2. 保持原始镜像不可变

`beautify-bundle.mjs` 的默认输出目录改为 `probe/_pretty/`，不再把派生格式化文件写进 `mirror/`。生成的 README 也使用 `pnpm dlx` 重跑命令。

## 3. Vite ESM 入口解析

`beautify-bundle.mjs` 在 Acorn 以 script 模式解析 `import.meta` 失败时，会回退到 module 模式。原入口 bundle 使用 `import.meta`，此前只检查 `sourceType: module` 错误文本会漏掉该情况。

## 4. Windows Node 24 的离线门退出

`verify-offline.mjs` 使用 `process.exitCode` 而不是在 fetch 请求完成后立即调用 `process.exit()`。原行为会在 Windows Node 24 的 libuv 句柄关闭阶段触发 `UV_HANDLE_CLOSING` assertion。修复后静态外联门通过；由于 Undici keep-alive 连接自然排空，退出时间可能较长。

## 5. 使用约束

- `probe/_pretty/` 只是阅读坐标；如果 token stream 不等，禁止将其当作可交付源代码。
- 原始 bundle 仍以 `mirror/`/`port/` 为字节真源。
- 上游升级时应重新检查这些补丁是否仍有必要，并优先向上游提交兼容修复，而不是永久分叉。
- 当前还没有产品 `package.json`；`vh doctor` 建议接入 `@playwright/test`，该建议暂缓到用户确认 scaffold 路径之后。现在的 Playwright 1.64.1 仅用于本地取证，安装在 gitignored `.cache/` 中；开始独立产品代码时再用 pnpm 建立受版本锁定的正式测试套件。
