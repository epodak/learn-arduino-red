## 📂 核心板块职责规范

### 1. 🏛️ `architecture/` - 系统结构真源
* **回答核心问题**：系统结构是什么？组件边界与硬约束在哪里？
* **收录内容**：核心架构拓扑、模块依赖关系、边界契约、时序与状态流。
* **规则**：严禁把临时调试命令或代码片段放于此处，只保留经过验证的全局架构事实。

### 2. ⚙️ `engineering/` - 工程实现规范
* **回答核心问题**：当前工程怎么做？
* **收录内容**：开发环境配置、构建与打包指南、代码规范、核心模块实现机制、日志与异常处理规范。
* **规则**：必须 100% 能够被当前环境和代码验证，代码改动后立即就地同步更新。

### 3. ⚖️ `decisions/` - 技术选型与架构决策 (ADR)
* **回答核心问题**：为什么做此决策？
* **收录内容**：关键技术选型、架构权衡记录。采用轻量 Markdown，必备 6 字段（决定、背景、备选方案、推导原因、后果与代价、生效状态）。
* **铁律**：**严禁在决策文档中复制代码实现细节！决策存 Why，工程存 How。**

### 4. 🔄 `workflow/` - 协作与工作流 SOP
* **回答核心问题**：团队与智能体如何协作？
* **收录内容**：Git 分支与发布规范、多 Agent 接力规范、验收标准与质检门禁。

### 5. 🎯 `strategy/` - 战略与演进路线
* **回答核心问题**：系统去向哪里？
* **收录内容**：阶段性演进目标、技术路线图、中长期规划与收敛验证指标。

### 6. 🗄️ `archive/` - 历史归档
* **回答核心问题**：哪些是已退出事实的历史过程？
* **收录内容**：已被替代的技术方案、已废弃接口说明、阶段性调试草稿与过时报告。
* **规则**：物理归档隔离，避免对 AI 决策造成认知污染。

## 🌿 文档园丁管理守则 (Docs Gardener v3.0)

1. **默认不新建原则 (防熵增)**：
   AI 的默认行为必须是**修改已有真源文档**，严禁遇到新问题就随意新建 Markdown。只有在当前代码库中完全不存在该主题、具备独立生命周期且无解释权冲突时，才允许新建。
2. **反形式主义与去编号税**：
   禁止使用 `000_`, `10_`, `ADR-001` 等伪编号，统一采用直观清晰的中文命名。
3. **零手抄记账**：
   禁止在文档内手抄版本修订表格，代码演进交给 Git Commit，长程调试过程沉淀至 `_dev_log/`，文档本身**只保留此刻唯一的最新事实**。
4. **反碎片化强制阈值 (先合并，再分裂)**：
   当两个文档服务于同一个工程对象、描述同一技术因果或依赖同一组实现时，强制就地合并，绝不分散创建。
5. **任务收尾「真源四审」**：
   * **真伪校准**：刚才的代码变动是否让已有文档失效？就地纠正。
   * **同源合一**：是否有散落同主题碎片？压制合并至唯一真源。
   * **野文件归位**：清理根目录与临时文件，归位至对应一级目录或 archive。
   * **代码可验证性**：文档中所有路径、参数和命令必须能通过当前环境验证。
